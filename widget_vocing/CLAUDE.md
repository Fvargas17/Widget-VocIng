# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

`widget_vocing` es una app Flutter (SDK ^3.13.2) para aprender vocabulario y frases en inglés de forma pasiva: muestra tarjetas breves (palabra, descripción, traducción, ejemplo de uso) que se pueden consultar rápidamente. El objetivo a largo plazo es que este mismo contenido aparezca en widgets nativos (Android) y en el Lock Screen (iOS), sin backend ni suscripción — todos los datos se almacenan localmente.

El vocabulario base viaja embebido en la app, pero puede crecer con **packs descargables** (paquetes de vocabulario) publicados como archivos JSON estáticos en este mismo repo (sin backend/microservicio): ver sección "Packs de vocabulario descargables" más abajo.

## Comandos habituales

```bash
flutter pub get              # instalar dependencias
flutter run                  # ejecutar la app (elige dispositivo/emulador disponible)
flutter analyze              # lint/análisis estático (usa package:flutter_lints/flutter.yaml)
flutter test                 # correr toda la suite de tests
flutter test test/widget_test.dart   # correr un solo archivo de test
flutter build apk            # build Android
flutter build ios            # build iOS (requiere macOS)
```

## Notas de arquitectura

- `lib/main.dart` define `WidgetVocIngApp` y `main()`. La navegación usa **rutas nombradas**: `/` → `HomeScreen`, `/packs` → `PackManagementScreen`, `/learned` → `LearnedWordsScreen`, `/settings` → `SettingsScreen`. El archivo re-exporta `HomeScreen` y `VocabularyCard` desde `screens/home_screen.dart` (vía `export`) para que `test/widget_test.dart` siga pudiendo importarlos desde `package:widget_vocing/main.dart` sin cambios. `WidgetVocIngApp` envuelve el `MaterialApp` en un `ValueListenableBuilder<String>` que escucha `selectedThemePresetIdNotifier` (ver sección "Sistema de temas" abajo) para reconstruirse con el `ThemeData` del preset activo cada vez que cambia. `main()` dispara `_loadPersistedThemePreset()` (lee el preset guardado y actualiza el notifier) sin `await` antes de `runApp()`, para no bloquear el primer frame.
- La app tiene un **menú lateral (`Drawer`)** compartido entre las cuatro pantallas, con cuatro destinos: Inicio, Administrar packs, Palabras aprendidas y Configuración (ver `lib/widgets/app_drawer.dart` y las pantallas en `lib/screens/`).
- `lib/screens/home_screen.dart` define `HomeScreen` (`StatefulWidget`, antes vivía en `main.dart` como `VocabularyScreen`) y `VocabularyCard`. En `initState`, `HomeScreen` carga **toda la lista** de vocabulario y el set de ids aprendidas (`getLearnedWordIds()`, ver `learned_words_service.dart`) de forma asíncrona y selecciona una palabra aleatoria inicial —excluyendo las ya aprendidas— para mostrarla en `VocabularyCard`. Mientras carga, se muestra un `CircularProgressIndicator`. El estado del ítem visible se guarda como el ítem en sí (`_currentItem`), no como índice, porque el pool de palabras activas (`_activeItems`, que excluye las aprendidas) cambia de tamaño en tiempo de ejecución. Hay dos `FloatingActionButton`: "Palabra anterior" (`Icons.arrow_back`) y "Otra palabra" (`Icons.arrow_forward`, en armonía visual con el anterior; garantiza que nunca se repita la palabra visible). Al avanzar, la palabra actual se empuja a un historial en memoria (`_history`, máximo 10, FIFO) que el botón "atrás" consume con `removeLast()` — no persiste entre reinicios de la app y no funciona como ida-y-vuelta (solo retrocede). Debajo de la tarjeta hay un botón "Marcar como aprendida" que llama a `markWordAsLearned()` y salta a otra palabra activa; si ya no quedan palabras activas, se muestra un mensaje en vez de la tarjeta. Tras la carga inicial, `_checkForNewPacks()` consulta en segundo plano si hay packs de vocabulario nuevos y no vistos (`checkForNewUndismissedPacks()`, ver abajo) y, si los hay, muestra un `AlertDialog` de solo aviso ("Ver" / "Ahora no") — ya no descarga nada inline. Si el usuario toca "Ver", navega a `/packs` (`PackManagementScreen`) y, al volver, refresca `loadVocabulary()` por si se descargó algo. En ambos casos (o si el diálogo se descarta de cualquier otra forma) se llama a `dismissPacks()`, así que ese mismo aviso no se repite en la siguiente apertura de la app mientras no se publique una versión más nueva del pack. El texto de pronunciación en `VocabularyCard` usa `Theme.of(context).colorScheme.onSurfaceVariant` (antes era `Colors.grey` hardcodeado) para respetar el tema activo.
- `lib/screens/pack_management_screen.dart` define `PackManagementScreen`, accesible desde el Drawer o desde el diálogo de aviso de `HomeScreen`. Consulta `fetchRemoteIndex()` y lo cruza con `getDownloadedPackVersions()` para listar **todos** los packs publicados con su estado (no descargado / actualización disponible / descargado), permitiendo descargar (`downloadPack()`) o eliminar (`deletePack()`) cada uno individualmente, con `RefreshIndicator` para reintentar y manejo simple de error si no hay red.
- `lib/screens/learned_words_screen.dart` define `LearnedWordsScreen`, accesible desde el Drawer. Cruza `loadVocabulary()` con `getLearnedWordIds()` para listar las palabras marcadas como aprendidas, con el conteo en el título del `AppBar`, y permite desmarcarlas (`unmarkWordAsLearned()`) para que vuelvan al pool aleatorio de `HomeScreen`.
- `lib/screens/settings_screen.dart` define `SettingsScreen`, accesible desde el Drawer. Lista los presets de `appThemePresets` (ver "Sistema de temas" abajo) dentro de un `RadioGroup<String>` con `RadioListTile` por preset; al elegir uno, persiste el id con `setSelectedThemePresetId()` y actualiza `selectedThemePresetIdNotifier.value`, lo que reconstruye `MaterialApp` en `main.dart` de inmediato.
- `lib/widgets/app_drawer.dart` define `AppDrawer` (recibe `currentScreen: AppScreen.home | AppScreen.packs | AppScreen.learned | AppScreen.settings` para resaltar el destino activo) y navega con `pushReplacementNamed('/')`/`pushReplacementNamed('/packs')`/`pushReplacementNamed('/learned')`/`pushReplacementNamed('/settings')` — se usan rutas nombradas en vez de referenciar los widgets de pantalla directamente para evitar un import circular entre el Drawer y las pantallas que lo incluyen.
- `lib/models/vocabulary_item.dart` define el modelo `VocabularyItem` (`id`, `word`, `pronunciation`, `description`, `translation`, `example`) con `VocabularyItem.fromJson`. `id` identifica la palabra de forma única para deduplicar al fusionar el pack base con packs descargados. `pronunciation` es una fonética intuitiva en español (no símbolos IPA), pensada para que se lea fácil (ej. `óver-uélmd`), y se muestra en `VocabularyCard` justo debajo de la palabra.
- `lib/data/vocabulary_repository.dart` expone `loadVocabulary()`, que fusiona el pack base embebido (`assets/data/vocabulary.json`, leído vía `rootBundle`) con todos los packs `.json` guardados en el directorio de documentos de la app (packs descargados previamente), deduplicando por `id`. Expone `debugSkipDownloadedPacks` (`@visibleForTesting`) para que los tests omitan la lectura de disco real.
- `assets/data/vocabulary.json` contiene el pack base de vocabulario (actualmente 5 palabras/frases de ejemplo), garantizado offline desde el primer arranque. Está registrado como asset en `pubspec.yaml`. **Para agregar una palabra al pack base, solo hay que editar este JSON — no hace falta tocar código.** Para agregar vocabulario nuevo sin republicar la app, usar packs descargables (ver siguiente sección).
- `lib/services/pack_service.dart` maneja la descarga y gestión de packs adicionales:
  - `fetchRemoteIndex()` consulta `content/packs/index.json` en GitHub raw content (retorna `null` sin lanzar si falla, p. ej. sin red).
  - `getDownloadedPackVersions()` (pública) lee de `shared_preferences` el mapa `packId → version` de lo ya descargado; la usan tanto `checkForNewPacks()` como `PackManagementScreen` para saber el estado de cada pack.
  - `checkForNewPacks()` retorna los packs del índice remoto que faltan o tienen una versión más nueva que la descargada (sin filtrar por "ya vistos" — la usa `PackManagementScreen`, que debe mostrar todo).
  - `checkForNewUndismissedPacks()` es igual, pero excluye los packs que el usuario ya descartó en el diálogo de aviso para esa misma versión (ver `dismissPacks()`); la usa el diálogo de `HomeScreen`.
  - `dismissPacks(packs)` registra en `shared_preferences` (clave `dismissed_pack_versions`, paralela a `downloaded_pack_versions`) qué packs/versión ya vio el usuario en el diálogo de aviso, para no repetir la notificación hasta que se publique una versión más nueva.
  - `downloadPack()` descarga y guarda un pack en disco y registra su versión en `shared_preferences`.
  - `deletePack()` borra el archivo local del pack y quita su entrada de `getDownloadedPackVersions()`, de modo que vuelve a listarse como disponible para descargar en `PackManagementScreen`.
  - Usa `HttpClient.connectionTimeout` (no `Future.timeout()`, que no cancela el socket subyacente) para no dejar conexiones colgadas sin red. Expone `debugDisableNetworkChecks` (`@visibleForTesting`) para que los tests no dependan de red real.
- `lib/services/learned_words_service.dart` guarda en `shared_preferences` (clave `learned_word_ids`, un `List<String>`/`Set<String>` de ids) qué palabras marcó el usuario como aprendidas/dominadas: `getLearnedWordIds()`, `markWordAsLearned(id)`, `unmarkWordAsLearned(id)`. Lo consumen tanto `HomeScreen` (para excluir esas palabras del pool aleatorio) como `LearnedWordsScreen` (para listarlas y permitir desmarcarlas).
- `lib/services/vocabulary_state_service.dart` (`VocabularyStateService`) es la única fuente de verdad de "cuál es la palabra actual" y su historial de navegación, persistida en `shared_preferences` (`vocab_state_current_id`, `vocab_state_history_ids`, este último ids en orden cronológico, máx. 10, FIFO) — reemplaza el estado en memoria que antes vivía solo en `HomeScreen`, para que la app y el widget nativo de Android (ver sección "Widget de Android" abajo) compartan siempre la misma palabra visible. Ningún método cachea nada en memoria de instancia: cada llamada (`loadState()`, `goToNextWord()`, `goToPreviousWord()`, `markCurrentAsLearned()`, `peekState()`) vuelve a leer `loadVocabulary()` y `getLearnedWordIds()` desde cero, porque el callback del widget corre en un isolate headless nuevo en cada interacción y no puede depender de estado previo. Cada método mutador termina llamando a un `_syncWidget()` privado que empuja los datos relevantes al widget nativo vía `HomeWidget.saveWidgetData()`/`HomeWidget.updateWidget()` (paquete `home_widget`), envuelto en `try/catch` silencioso porque en tests ese `MethodChannel` no tiene handler registrado. Expone `debugSkipWidgetSync` (`@visibleForTesting`) para que los tests lo desactiven explícitamente — **necesario**, no opcional: sin él, `test/widget_test.dart` cuelga en `pumpAndSettle()`, porque en el entorno de test un `MethodChannel` sin handler no lanza excepción de inmediato (quedaría atrapada por el `try/catch` sin problema), sino que el mensaje queda en buffer sin resolver nunca dentro del reloj simulado de `flutter_test`.
- `lib/services/home_widget_callback.dart` define `backgroundCallback(Uri? uri)`, el entry point (`@pragma('vm:entry-point')`) que `home_widget` invoca en un isolate headless cuando el usuario toca un botón del widget con la app cerrada. Es deliberadamente delgado: solo interpreta `uri.host` (`next`/`previous`/`learned`) y delega en los mismos métodos de `VocabularyStateService` que usa `HomeScreen`, así ambos caminos comparten idéntica lógica (exclusión de aprendidas, no repetir la palabra visible, límite de historial). Se registra una sola vez en `main()` (`lib/main.dart`) vía `HomeWidget.registerInteractivityCallback(backgroundCallback)`, antes de `runApp()`.
- `analysis_options.yaml` excluye `build/**`, `android/**`, `ios/**`, `web/**` del análisis estático y aplica el set de lints `flutter_lints`.
- `test/widget_test.dart` valida, en un único `testWidgets`, que `WidgetVocIngApp` muestre el indicador de carga, luego una tarjeta de vocabulario tras resolver la carga async del asset, y que al tocar el `FloatingActionButton` con tooltip "Otra palabra" (hay dos FAB en `HomeScreen`, así que no se puede buscar solo por tipo) la palabra mostrada cambie. Al inicio de `main()` se activan `pack_service.debugDisableNetworkChecks` y `vocabulary_repository.debugSkipDownloadedPacks` en `true`, y se llama a `SharedPreferences.setMockInitialValues({})`: los tests de widgets no deben depender de red, de I/O de disco real, ni de un canal de plataforma real de `shared_preferences` (sin el mock, `HomeScreen.initState` cuelga `pumpAndSettle()` esperando indefinidamente `getLearnedWordIds()`). El reloj simulado de `flutter_test` no puede esperar de forma fiable operaciones asíncronas reales de ese tipo. **Importante:** mantener todas las aserciones del flujo principal en un solo test — se comprobó que separar la carga inicial y el tap en dos `testWidgets` distintos del mismo archivo provoca que el `pumpAndSettle()` del segundo test cuelgue (timeout), por una interacción entre la carga real de assets vía `rootBundle` y el reloj simulado de `flutter_test` al reutilizarse entre tests.
- `pubspec.yaml` fija `dependency_overrides: path_provider_foundation: 2.4.1`. Sin esto, `flutter test`/`flutter build` fallan en esta máquina porque el Flutter SDK vive en una ruta con espacio (`C:\SDK Flutter\flutter`), lo que rompe la compilación de "native assets" de `objective_c` (dependencia transitiva de versiones más nuevas de `path_provider_foundation`). Esta versión evita esa dependencia.

## Sistema de temas de UI

No hay ningún paquete de manejo de estado (Provider/Riverpod/Bloc) en el proyecto — toda la app usa `StatefulWidget` + `setState`. El sistema de temas reutiliza ese mismo estilo y añade una única pieza de estado reactivo global:

- `lib/theme/app_theme_roles.dart` define `AppThemeRoles`, el set fijo de 7 colores semánticos que debe rellenar cada preset (`primary`, `accent`, `background`, `card`, `text`, `textSecondary`, `softAccent`) — mantener esta lista corta y estable es lo que permite agregar presets nuevos sin tocar el resto del sistema.
- `lib/theme/app_theme_builder.dart` define `buildThemeFromRoles(AppThemeRoles roles)`, la única función que traduce esos 7 colores a un `ThemeData` (Material 3) completo: `ColorScheme`, `scaffoldBackgroundColor`, `appBarTheme` (fondo `accent`), `cardTheme`/`drawerTheme`/`dialogTheme` (fondo `card`, bordes muy redondeados — `24` en Cards, `20` en FAB/diálogos), `floatingActionButtonTheme`/`listTileTheme`/`progressIndicatorTheme`/`textButtonTheme` (color `primary`), y `textTheme` con títulos en negrita. Todos los presets pasan por aquí — no hay lógica de theming duplicada entre presets.
- `lib/theme/app_theme_preset.dart` define `AppThemePreset` (`id`, `displayName`, `themeData`) y el catálogo `appThemePresets`, hoy con **5 presets**: "Serene Wellness" (verde salvia oscuro `#5C7A52` + fondo verde `#8AA482` + card tostada `#EBD8C3`, el original/por defecto) y cuatro presets claros que comparten el mismo `primary` verde salvia `#8AA482` pero varían su `accent`/personalidad — "Café claro" (`#B89B7A`), "Terracota" (`#B8755D`), "Café" (`#7A5C48`) y "Azul petróleo" (`#42666A`), todos con fondo claro neutro y card casi blanca. Agregar un preset nuevo es solo sumar una entrada con sus `AppThemeRoles` — no hace falta tocar `main.dart`, `app_drawer.dart` ni `settings_screen.dart`. `resolveThemePreset(id)` cae al primer preset del catálogo si el id guardado ya no existe (p. ej. se eliminó ese preset en una versión futura).
- `lib/services/theme_notifier.dart` expone `selectedThemePresetIdNotifier` (`ValueNotifier<String>`), la única pieza de estado reactivo global de la app. Vive en un archivo aparte de `main.dart` para evitar un import circular con `settings_screen.dart` (que necesita escribirlo al elegir un preset, y `main.dart` necesita leerlo para reconstruir `MaterialApp`).
- `lib/services/theme_service.dart` persiste el id del preset elegido en `shared_preferences` (clave `selected_theme_preset_id`), con el mismo patrón de funciones top-level que `learned_words_service.dart`: `getSelectedThemePresetId()` / `setSelectedThemePresetId(id)`.
- El único color hardcodeado que existía en toda la app (`Colors.grey` en la pronunciación de `VocabularyCard`) se migró a `Theme.of(context).colorScheme.onSurfaceVariant` para que respete el preset activo.

## Packs de vocabulario descargables (sin backend)

Para hacer crecer el vocabulario sin republicar la app ni mantener un backend, el contenido adicional se distribuye como archivos JSON estáticos servidos vía GitHub raw content:

- `content/packs/index.json`: manifiesto con la lista de packs disponibles (`id`, `name`, `version`, `wordCount`, `file`).
- `content/packs/pack_000N.json`: un pack = un array de palabras con el mismo formato que `assets/data/vocabulary.json`, con `id` único por palabra (`pack_000N_000M`).
- La app consulta `https://raw.githubusercontent.com/Fvargas17/Widget-VocIng/main/widget_vocing/content/packs/index.json` (ver `_indexUrl` en `pack_service.dart`) **desde la rama `main`**. El contenido no está "publicado" para la app hasta que ese archivo exista en `main` (push directo o merge de PR).
- **Publicar contenido nuevo no actualiza apps ya instaladas**: el código Dart que sabe consultar/descargar packs debe estar compilado en la app del dispositivo. Si solo cambia contenido (JSON), basta con publicar en `main` y reabrir la app; si cambió la lógica de packs, hay que reinstalar con `flutter run`/`flutter build` primero.
- El chequeo de packs nuevos corre una sola vez, en `initState`, así que hay que cerrar la app por completo y reabrirla para que vuelva a correr.
- Para el flujo detallado de cómo crear y publicar un pack nuevo (plantilla lista para usar), ver `Plantilla_Nuevo_Pack_Vocabulario_widget_vocing.md` en la carpeta de skills de Claude del usuario.

## Widget de Android (menú de apps, no lock screen todavía)

La app tiene un widget nativo de Android tradicional (agregable desde el launcher, no la pantalla de bloqueo — eso es Etapa 4, sin evaluar todavía), implementado con el paquete `home_widget` (pub.dev), que muestra **palabra + pronunciación + ejemplo** (sin traducción) y tres botones: siguiente, anterior, marcar como aprendida. Comparte el mismo estado persistido que `HomeScreen` (ver `VocabularyStateService` arriba), así que ambos siempre muestran la misma palabra y se sincronizan en cualquier dirección.

- `android/app/src/main/kotlin/com/example/widget_vocing/VocabularyAppWidgetProvider.kt`: extiende `HomeWidgetProvider` (clase base de `home_widget` que ya inyecta el `SharedPreferences` del plugin en `onUpdate`). Rellena un `RemoteViews` con los datos guardados por `_syncWidget()` (`widget_word`, `widget_pronunciation`, `widget_example`, `widget_empty`) y conecta los tres botones (`widget_btn_previous`, `widget_btn_next`, `widget_btn_learned`) a `HomeWidgetBackgroundIntent.getBroadcast(context, Uri.parse("vocabwidget://previous|next|learned"))`, que dispara `backgroundCallback` en Dart sin abrir la app. Tap en el cuerpo del widget (`widget_root`) abre la app vía `HomeWidgetLaunchIntent`.
- `android/app/src/main/res/layout/vocabulary_widget_layout.xml`: `LinearLayout` + `TextView`/`Button` planos — `RemoteViews` no soporta `ConstraintLayout` ni widgets de Material.
- `android/app/src/main/res/xml/vocabulary_widget_info.xml`: metadata del widget (tamaño mínimo, layout inicial). `updatePeriodMillis="0"` es intencional: el widget se refresca de forma reactiva (`HomeWidget.updateWidget()` tras cada mutación de estado), no por polling periódico.
- `android/app/src/main/AndroidManifest.xml` registra manualmente, además del `<receiver>` del propio `VocabularyAppWidgetProvider`: (1) un `<intent-filter>` adicional en `MainActivity` para la acción `es.antonborri.home_widget.action.LAUNCH`, y (2) el `<receiver android:name="es.antonborri.home_widget.HomeWidgetBackgroundReceiver">` + `<service android:name="es.antonborri.home_widget.HomeWidgetBackgroundService">` que requiere el plugin para ejecutar el callback en background. **Importante:** el manifest del propio paquete `home_widget` (`AndroidManifest.xml` de la librería) no declara estos componentes — no se auto-fusionan por manifest merger, hay que declararlos a mano en la app (confirmado inspeccionando el `.pub-cache` del paquete; el ejemplo oficial de `home_widget` los declara igual).
- Para agregar el widget al home screen de un dispositivo/emulador: instalar la app (`flutter run`/`flutter install`), abrirla al menos una vez (así se puebla el estado inicial vía `_syncWidget()`), y luego mantener presionado el home screen → Widgets → "Palabra de vocabulario".

## Estado del roadmap

- **Etapa 1 (datos separados de la UI): completa.** El contenido vive en `vocabulary.json`, no en `main.dart`.
- **Etapa 2 (hacer la app útil): completa.** Selección de palabra aleatoria al iniciar, botón para cambiar de palabra manualmente (sin repetir la actual), pronunciación en texto (fonética intuitiva) en la tarjeta.
- **Etapa 2.5 (packs de vocabulario descargables): completa.** Ver sección "Packs de vocabulario descargables" arriba. Incluye navegación con menú lateral (Inicio / Administrar packs / Palabras aprendidas) y una pantalla dedicada (`PackManagementScreen`) para descargar, actualizar o eliminar cada pack individualmente — el diálogo de aviso inicial ya no descarga por sí solo, solo notifica y redirige a esa pantalla.
- **Etapa 2.6 (palabras aprendidas + navegación con historial): completa.** Botón para marcar la palabra visible como aprendida/dominada (`learned_words_service.dart`), lo que la excluye del pool aleatorio de `HomeScreen`; tercera sección del Drawer (`LearnedWordsScreen`) con el conteo y la posibilidad de desmarcarlas; botón "atrás" en `HomeScreen` con historial en memoria (máx. 10 palabras, no persistente).
- **Etapa 3 (widget de Android): completa.** Widget tradicional desde el menú de apps (no lock screen), con paridad completa de navegación/aprendidas respecto a `HomeScreen` gracias al estado compartido de `VocabularyStateService`. Ver sección "Widget de Android" arriba.
- **Etapa 3.5 (sistema de temas de UI): completa.** Pantalla de Configuración (`SettingsScreen`, cuarta sección del Drawer) con selector de preset de tema; catálogo de 5 presets (`lib/theme/`) construidos sobre un set común de roles semánticos (`AppThemeRoles`): "Serene Wellness" (por defecto, verde salvia + crema, ver sección "Sistema de temas de UI" arriba) y cuatro variantes claras ("Café claro", "Terracota", "Café", "Azul petróleo"). El modo oscuro queda para cuando el proyecto lo retome explícitamente.
- **Etapa 4 (Lock Screen en iPhone): no iniciada.**
